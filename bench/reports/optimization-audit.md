# Token Forge optimization audit

Date: 2026-10-09. Model: `claude-opus-5-5`. Evidence: `reports/baseline-results.json` (generated by `scripts/optimization.py` from the tracked `reports/benchmark-report.json`). The optimization that was implemented and its A/B result are in `final-comparison.md`.

All token counts are API usage logged in the run transcripts (provider-reported). Costs are those counts priced at the list prices in `benchmark.config.json` `pricing` (source: the [Claude pricing page](https://platform.claude.com/docs/en/about-claude/pricing), effective 2026-10-09: input $4, 5-minute cache write $5, 1-hour cache write $8, cache read $0.20, output $20 per million tokens), checked run by run against Claude Code's own `total_cost_usd`. The cost split by content ("attribution") is a model-based estimate and is labelled as such. Token Forge's own overhead (hook context, skill listing, nested model calls) is part of every Token Forge figure.

## 1. What was inspected

- The plugin: hooks (`session-start`, `prompt-router`, `kit-router`, `code-redirect`, `context-watch`, `checkpoint`), `lib/lean.mjs` (the settings it writes: tool denies, `autoCompactWindow`), the `tkit`/`tmap` native tools.
- The benchmark: `runner/bench.py` (CLI, sandboxing, run loop), `isolation.py` (frozen environments, preflight validator), `telemetry.py` (transcript parser), `evalkit.py` (graders), `report.py`; the task packs under `tasks/` (the baseline covers 37; `ruby-cli` is excluded in the config); two agents with identical sandboxes: `native` (plain Claude Code) and `token-forge` (Claude Code plus the plugin at `lean: balanced`).
- The existing baseline: 83 executed runs, CLI 2.1.293. Native: 43 runs over 37 tasks. Token Forge: 40 runs over 36 tasks (no `memory-followup` run), three plugin builds the config declares equivalent (`1d360dd5…`, `31952bff…`, `b9471cc0…`). Every run completed.

Python tests: `python3 -m unittest discover -s bench/runner -p 'test_*.py'` (18 tests). They cover pricing and TTL splitting, streamed-output dedup, first request, cache-miss vs compaction, idle gaps per thread, hook durations, rusage, retelemetry field diffing, the validator window, attribution sums and the statistics.

Not measurable here, and reported as such: provider-side caching beyond what usage reports (the TTL split is provider-reported per request); the TTL API-key sessions get (by a static reading of Claude Code 2.1.295: 5 minutes for API-key sessions, 1 hour for a subscription login's main thread; every run here used a subscription login); peak memory and CPU for the baseline.

## 5. Bottlenecks, ranked by measured impact

1. **Visible output: 45.8% of Token Forge cost.** By character count (an estimate), about 96% of it is Bash tool input, which carries the file content (`tkit edit`) along with the build and test commands, and about 4% is prose. Native wrote 71 files with the Write tool and none of them twice; Token Forge writes through Bash, where rewrites were not measured. This is the deliverable, and Token Forge already writes 33% less of it than native; no reduction was found that would not risk completeness.
2. **Cache writes at the 1-hour TTL: 39.6% of cost.** This cuts across the parts above. Claude Code wrote every cache entry of the main sessions in all 83 runs with the 1-hour TTL (2× input); 5-minute writes cost 1.25×. If every write had been a 5-minute write and none had expired, the suite would have cost 14.8% less ($4.82 of $32.46 for Token Forge, $6.31 of $42.50 for native). No pause between requests exceeded 300 s (maximum 270.4 s Token Forge, 184.7 s native). That is a property of headless runs, though: an interactive user who pauses longer than 5 minutes pays a full re-write of the context, at 25× the price of a read.
3. **Thinking: 31.8% of cost, and Token Forge's only regression.** Token Forge spends more on thinking than native: +$0.042 per task (95% CI +$0.005 to +$0.079; pooled +19.0%), +1,684 thinking tokens per task (CI +366 to +3,001). The excess sits in the first request, planning before the repository has been looked at: first-request thinking is higher on 17 of the 23 tasks where it differs (sign test p = 0.035), pooled +565%. Both tasks where Token Forge costs more than native come from this:
   - `c-cli` +9.5% ($1.372 → $1.503): first-request thinking 11,308 → 23,273 tokens, thinking cost $0.367 → $0.705, the rest down $0.21. The run was a cold start, but that is not the cause: its first request carried 12,722 context tokens, and its initial-context cost ($0.127) is no higher than native's ($0.130).
   - `perl-cli` +5.4% ($1.312 → $1.383): first-request thinking 46 → 26,545 tokens, thinking cost $0.500 → $0.784.
4. **Tool results and context: 13.5% + 9.0%.** Both are already 37–50% below native.
5. **Cache misses: none in Token Forge,** one in native (483 tokens). Nothing to gain.

## 6. The three highest-impact opportunities

| | Opportunity | Measured size | Confidence | Decision |
|---|---|---|---|---|
| 1 | Up-front planning thinking: steer the first call to look at the repository before planning, keep the plan short and never draft code in thinking | Thinking is 31.8% of cost; the excess over native is +$0.042 per task, about 5% of mean cost | Highest: the one measured regression, a clear mechanism, a one-paragraph prompt change that touches neither code paths nor reads, reversible by an env var | **Implemented and measured** (`final-comparison.md`): list cost −15.5% per task (95% CI −20.8% to −9.8%), quality unchanged within resolution, so `TFORGE_PLAN=look` is now the default in main sessions (`TFORGE_PLAN=0` turns it off). `TFORGE_PLAN=brief` (plan briefly, nothing else) was the ablation and stays opt-in |
| 2 | Cache-write TTL: 5-minute writes instead of 1-hour | Up to −14.8% of cost in headless runs without long pauses | Low as a default: it costs interactive users money whenever they pause more than 5 minutes, and only measures well in a benchmark without pauses. Claude Code has environment variables for it. `FORCE_PROMPT_CACHING_5M=1` was verified with a smoke run: all 6,113 cache-write tokens were 5-minute writes, none 1-hour, and the list cost matched Claude Code's own. `CLAUDE_CODE_PROMPT_CACHE_TTL` was not run, because the bench's preflight validator refuses it | Not implemented. Re-priced on the A/B (a model: no expiry happened), one pause over 5 minutes mid-session costs 1.26–1.42× the run's whole saving (per-run median). A conditional candidate for headless automation only (`final-comparison.md`, E) |
| 3 | Tool-result and context volume | 22.5% of cost, already halved against native | Medium-low: the remaining volume is mostly the files a task must read | Not implemented |

## 7. Other observations

- The Claude Code CLI is not pinned. The baseline ran on 2.1.293 and the A/B on 2.1.295 with a newer, uncommitted Token Forge build (`autoCompactWindow`, more lean denies), so the A/B arms are compared with each other, not with the baseline.
- No benchmark run used a subagent: every write was a main-session 1-hour write. In this machine's own Claude Code transcripts, subagent writes are almost all 5-minute writes (28.3M of 28.4M tokens, provider-reported split). Polling loops in `kit-router.mjs` are already capped below 5 minutes when a 5-minute TTL applies.
- The tracked report files are rewritten by every `bench.py run`, including failed launches. They were restored from the copy taken just before the A/B launch: the baseline report regenerated with the new telemetry from the same 83 runs (sha256 verified). The environment manifests were left as `bench.py env build` rebuilt them for the A/B (Claude Code 2.1.295, plugin build `c9de32debeea`), so `bench.py report` and `bench.py run` now keep 2.1.295 runs only and would rebuild these reports without the baseline.
